?一句话: RAG 是什么?

RAG(Retrieval-Augmented Generation,检索增强生成) 是一种让大模型 「先查资料、再写答案」的技术。提问时,系统先到你的知识库里找出最相关的原文片段, 把它们和问题一起交给大模型,要求模型只依据这些资料作答,并在回答中标明出处。

🎯 把它想成一个场景: 一位记忆力超强但从不看书的专家(大模型), 你派一名助手(检索器)在你提问的瞬间去资料室(知识库)把相关书页(片段)搬来, 专家只看着书页回答,还告诉你内容出自哪本书第几页 —— 这就是 RAG。

1为什么需要 RAG?

只用大模型对话(不带 RAG)有三个硬伤,而 RAG 恰好都能解决:

痛点表现RAG 的解法
知识幻觉模型会一本正经地编造它不知道的事实 只依据你提供的资料回答,答不出的会说"资料里没有",不再瞎编
知识过时训练数据截止于某个时间点 资料随传随用,最新公告、今天的文档都能立刻参与回答
没有私有数据公司文档、教材、个人笔记不在模型知识里 资料只存在你本机,模型按需"查"它 —— 数据不出门,天然隐私
✅ 额外的收获 —— 可溯源: 每个回答都带 [1][2] 编号和「文档 + 页码」, 你可以人工核对答案对不对,这在学习、写作、审计场景里价值巨大(微调做不到这一点)。

RAG vs 微调(Finetune)

RAG(检索增强)微调
目标让模型知道/引用你的资料让模型学会一种行为/风格(如模仿客服口吻)
成本只需文档,按需检索需要标注数据 + GPU 训练
更新资料上传新文档即生效(秒级)每次都要重新训练
可溯源可标注引用页码 ✅不可溯源
适合知识问答、资料整理(本应用场景)风格迁移、专用格式输出

工程上的最佳实践常常是「RAG 打底 + 微调调风格」,两者不冲突。

2RAG 完整流水线(本应用的 5 个环节)

  1. 上传文档(知识库页) → 解析: PDF 逐页提取文字并记录页码、Word/网页提取正文;
  2. 分块 Chunking → 把长文档切成 400 字左右的小块,块与块保留重叠;
  3. 嵌入 Embedding → 每块文字经本地 bge 模型变成 512 维向量,连同原文存入向量库;
  4. 混合检索 Hybrid Retrieval(问答时发生) → BM25 关键词 + 向量语义两路召回,RRF 融合排序;
  5. 生成 Generation → 把命中的片段编号为 [1][2]… 拼进提示词,大模型依据它们流式作答并标注引用。

前 3 步在文档上传时一次性完成(也叫离线索引 Indexing); 后 2 步发生在你每次提问时(也叫在线推理 Inference)。

🔍 想亲眼看每个环节? 上传文档时盯住任务进度条(解析→分块→向量化→入库); 提问后点回答上方的「查看检索过程」,能看到两路检索各自的排名和融合分。

3你(新手)需要先懂的最小知识清单

  • 文档 ≠ 答案仓库: 系统检索的最小单位是「分块」,不是整篇文档 —— 所以分块质量决定一切;
  • 向量 = 文字的"语义指纹": 意思相近的句子,向量也相近(数学上夹角小);
  • 两个检索通道互补: 关键词(精确) + 语义(灵活),RAG 生产环境几乎都用这种混合方案;
  • 答案质量 = 检索质量 × 模型质量: 检索不到,再强的模型也答不对 —— 排查问题时先看「查看检索过程」。

1启动与首次准备(约 2 分钟)

  1. 双击根目录的 启动GreenRAG.bat —— 首次运行请先跑 一键安装.bat(自动创建虚拟环境、用清华镜像装齐依赖,约 5~15 分钟取决于网速)。
  2. 打开窗口后,程序会弹出新手引导。第一站: 点左侧「环境检查」→「重新检测」, 看到全绿 ✓ 就完成了(缺什么按条目右侧的国内镜像链接或复制命令补齐)。
  3. 嵌入模型是唯一需要联网下载一次的组件(约 95MB,自动走 hf-mirror 国内镜像)。 若首次未下载,到「设置 → 嵌入模型」点「下载模型」。

2关于大模型: 两种选择(约 1 分钟)

方案怎么做适合谁
内置演示模式(默认) 什么都不用填。回答由模板生成,但上传→检索→引用→分页标注全流程真实可跑 第一次体验 / 没有 API Key
在线 API 「设置 → 大模型」选服务商预设(DeepSeek / 智谱 / 通义 / SiliconFlow / Ollama 等), 填入 API Key → 「测试连接」成功即可 想得到最强的智能回答(按量付费)

🖥️ GGUF 本地推理小课堂: GGUF 是 llama.cpp 使用的量化模型格式(4bit 等), 下载即用无需转格式。推理引擎 llama-server 是官方免编译程序: 有 NVIDIA 显卡装 CUDA 版, 在设置里把「卸载层数」调到合适数值(0=纯CPU;模型不大就设满 99),模型权重就会放进显存, 速度通常比 CPU 快数倍;没有独显则自动用 CPU。显存占用可在任务管理器 → 性能 → GPU 查看。
💰 国内推荐 DeepSeek(便宜好用)或智谱 GLM;两者都支持 OpenAI 兼容接口, 本应用预设已帮你填好地址和模型名。Ollama 则完全免费离线,适合学生党(需另装 Ollama)。

3上传你的第一批文档(约 2 分钟)

  1. 进入「知识库」页,把 PDF / Word / TXT / Markdown 拖进虚线框(可多选),或粘贴网页链接回车;
  2. 看任务卡片跑完 解析 → 分块 → 向量化 → 入库;统计区出现「X 篇 / Y 个分块」即为成功;
  3. 点文档行「查看分块」: PDF 的每一块都标了第几页 —— 这就是回答里"第 X 页"的来源; 用搜索框验证你的关键内容有没有被切进来;
  4. 点「打开原文」可随时用系统软件打开备份的原文件核对。
⚠️ 常见失败: 上传扫描版 PDF(纯图片)会提示"没有文字层"。程序暂不支持 OCR, 请用文字版 PDF(能选中文字的)、Word 或把内容存成 TXT。

4提问并读懂一次回答(约 3 分钟)

  1. 进入「智能问答」,输入与文档有关的问题,回车;
  2. 观察回答中的 [1] [2] 绿色角标和下方的「答案引用的来源」卡片 —— 卡片上写着 文档名 + 第几页,点击即可在检索列表里定位到原文片段,验证答案是否忠于资料;
  3. 点「🔍 查看检索过程」: 这是全场最有教学价值的按钮。 你会看到向量排名(语义)和关键词排名(字面)常常不一致 —— 这正是混合检索存在的意义:
你的问题向量路擅长BM25 路擅长
"用什么方法提高模型精度?"✓ 找到"微调 / 增加训练数据"等换说法的段落 —(字面词没对上)
"GB/T 9704 是哪个标准?"—(可能跑偏)✓ 精确命中含"GB/T 9704"的段落
💡 提问小技巧: 问题越具体、越贴合文档里的措辞,命中率越高。 一次只问一个问题;答非所问时,先看「检索过程」是不是根本没命中,再决定换问法或调整参数。

5遇到问题的排查顺序(FAQ 简版)

  1. 回答"没找到相关内容" → 打开「查看检索过程」看 最佳余弦: 分数低说明文档里确实没有 / 问法差异太大;分数高却答没找到 → 调低「无相关判定阈值」;
  2. 检索有命中但回答质量差 → 试试真实大模型(而非演示模式),或在设置里调大 top_k;
  3. 改了分块大小没效果 → 改完后需要到知识库页「重建全部索引」才会生效(界面会提示);
  4. 上传很慢 / 卡住 → 首次向量化要加载模型(10~60 秒),看任务卡片的实时进度;笔记本可用 CPU 跑,慢是正常的。

1最重要的一组: 分块参数

文档先切成块再向量化。块的大小决定「检索的瞄准镜」有多宽:

参数当前默认调小 →→ 调大
chunk_size 分块大小400 字 命中更精准、引用页码更精确,但上下文碎片化(要点可能被切散) 上下文完整连贯,但一个块里话题混杂,检索容易"瞄不准"
overlap 重叠80 字 块之间几乎无冗余 答案"正好骑在切缝上"的概率更低,代价是少量重复存储

实验建议: 一般文档 300~600 字是甜区;代码/合同条款适合 200~300; 章节式长文可到 800。每次只改一个参数 → 重建索引 → 用 5 个问题对比效果,这就是最朴素的 A/B 实验。

2检索与生成参数

参数默认作用 / 什么时候动它
top_k 送入模型的片段数6 每个问题带几块原文给模型。问"综述型"问题调到 8~10;问"找一句话"可以 3~4。越大越占上下文、越慢
bm25_top / dense_top 各路召回数100 混合检索内部"海选"名额。库很大(万级块)时可适当调大;通常不必动

3嵌入模型选择

  • 本地 bge-small-zh-v1.5(默认): 95MB,CPU 可跑,中文效果好,完全免费离线 —— 个人学习首选;
  • API 嵌入: 想要更强语义理解(或嫌本地占资源)时,可用智谱 embedding-3、OpenAI text-embedding-3 等。 ⚠ DeepSeek 官方不提供 embedding,选它当对话模型时嵌入仍要用本地模型 —— 两者互不影响,本应用默认就是这个组合。
换嵌入模型/分块参数后,记得「重建全部索引」;不同参数组合产出的向量不通用。

1嵌入(Embedding)与余弦相似度

嵌入模型把一段文字压成一个 512 维向量(一串小数)。同一模型编码的句子, 语义越接近,向量"方向"越一致。检索时把问题也编码成向量,计算它与库中每个向量的夹角余弦:

cosine_similarity(A, B) = (A·B) / (|A|·|B|) ∈ [−1, 1]

接近 1 → 语义高度相关。向量检索可以理解为: 在几千个"句子方向"里找指向最接近问题的那些。 注意它比较的是整块文字的整体语义,所以"块太大、话题太杂"会稀释相似度 —— 这就是分块重要的原因。

2BM25: 经典的关键词检索

BM25 是搜索引擎的常青树算法。它对每个词打分,综合考虑: 词频(出现次数)、逆文档频率(越稀有的词越值钱)、长度归一化(越长的文档词频越要打折)。

score(D,Q) = Σ (词i在D中频率的加权) × IDF(词i)

中文无法按空格分词,所以需要 jieba 分词先切词。BM25 完全基于字面: 问"深度学习和机器学习区别",它能命中含这些术语的段落,但找不到只写"神经网络 vs 决策树"的段落 —— 那是向量检索的主场。

3混合检索与 RRF 融合

既然两条路各有盲区,工业界标准做法是都跑,再融合。本应用用 RRF(Reciprocal Rank Fusion, 倒数排名融合)—— 不看原始分数(两种分数不可比!),只看各自榜单里的名次:

RRF(块x) = 1/(k + 名次ᵃᵢ) + 1/(k + 名次ᵇᵢ),其中名次从 0 开始,k = 60

一个块只有在至少一路里排名很靠前才能得高分,两路都靠前则几乎必进 top_k。 排名融合的好处: 绕开了"BM25 分数与余弦相似度单位不同、不能直接相加"的问题。 在「问答」页的检索过程面板里,你能看到每个候选块的 向量#n / 关键词#n / RRF 分, 自己手算一遍就能彻底理解。

候选块向量名次关键词名次RRF = 1/(60+r₁) + 1/(60+r₂)
块 A#1#30.0164 + 0.0159 ≈ 0.032
块 B#45未召回0.0095(只有一路)

结论: 块 A 两路都靠前 → 总分最高。块 B 语义沾边但没命中关键词,得分骤降 —— 融合会"惩罚"只有单路支持的结果。

4提示词组装: 答案与引用是怎么来的

后端把检索结果拼成「参考资料区」,并给模型立下规则(在「设置 → 自定义提示词」可以追加自己的要求):

[1] 来源: 《深度学习入门》第23页 内容: (原文片段…) [2] 来源: 《…》第45-46页 内容: (原文片段…) 系统规则: 只能依据以上资料回答;用到哪条资料就在对应句末标 [编号]; 资料与问题无关时,回答:知识库中暂未找到相关内容。

回答结束后,程序扫描输出里的 [n],对照资料表生成「来源卡片」。 这就是你看到"第 X 页"的完整链路 —— 没有页码标记的 PDF 或网页,则只标注文档名(Word/网页没有真实的"页"概念)。

5下一步可以学什么

  • 重排序 Rerank: 先用轻量检索召回 50~100 条,再用交叉编码器精排 top_k —— 精度再上一个台阶(本应用把两路名次融合,已内含"重排"思想);
  • 查询改写: 复杂问题先让模型拆成多个子查询,分别检索再汇总;
  • 评估: 准备 20~50 个(问题, 期望段落)对,算命中率 —— 参数怎么调,用数据说话;
  • 向量数据库: 数据量到几十万分块后,本应用的纯 NumPy 检索会变慢,可迁移 FAISS / Milvus 等。

?常见问题 FAQ

模型 / 连接

  • 回答显示"尚未配置大模型 API"? 到「设置 → 大模型」选预设填 Key 并「测试连接」; 先用「内置演示模式」也能体验完整流程。
  • DeepSeek Key 填了还报错? 确认选的是 OpenAI 兼容预设、模型名是 deepseek-chat; DeepSeek 无 embedding 不影响使用(嵌入默认本地模型)。
  • Ollama 怎么用? 安装 Ollama → 命令行拉取模型(如 ollama pull qwen2.5:7b) → 在预设里选「Ollama(本地)」,base_url 填 http://localhost:11434/v1。
  • 怎么用本地 GGUF 模型? ①「环境检查」页按 GGUF 引擎条目下载 llama-server.exe 放进 models/llama; ② 下载 .gguf 模型(见设置页 GGUF 面板的国内镜像链接)放进 models/gguf; ③ 「设置 → 大模型」切到「本地 GGUF」,选模型 → 调 GPU 卸载层数 → 「▶ 启动模型」。 首次提问即走完整 RAG 链路,回答同样标注文档与页码。
  • GPU 卸载怎么判断该设多少? 设置页会显示你的显卡型号与显存。0 = 纯 CPU;把层数设满 = 整个模型放进显存(推荐,前提是显存放得下: 7B 量化模型约 4~6GB)。显存不足时降低层数即可, 程序会在下次启动时自动应用。

文档 / 知识库

  • 为什么 PDF 能标页码,Word 不能? PDF 是版式文档,天然有页;Word 是流式文档, 程序没做排版引擎,无法知道内容落在第几页 —— 这是业界普遍做法。
  • 上传重复了? 程序按内容哈希自动跳过重复文档,先删除旧文档即可重新上传。
  • .doc 老格式为什么不行? 格式闭源难解析。用 Word/WPS「另存为 .docx」即可。

回答质量

  • 答非所问? 90% 是检索没命中。看「查看检索过程」: 余弦都很低 → 换问法或文档没内容; 排名正常但答案差 → 换真实大模型 / 调大 top_k。
  • 答案与原文不一致? 点击来源卡片核对原文;仍不符就把「温度」降到 0.1~0.2, 并保持「仅知识库回答」开启。
  • 检索速度? 个人级(几千块)毫秒级;块数达几十万后建议换专业向量库(见进阶篇)。

环境 / 安装

  • 国内下载太慢? 所有 Python 依赖安装都走清华镜像(一键安装.bat); 模型走 hf-mirror;仍失败可用 ModelScope 魔搭(见环境检查页的复制命令)。
  • 无法从微软商店下载 / 一运行就弹微软商店? GreenRAG 的所有依赖都不需要微软商店。 弹商店通常是因为系统只装了"商店版 Python 占位符": 到「设置 → 应用 → 高级应用设置 → 应用执行别名」关闭 python.exe / python3.exe 两个开关, 再到「环境检查」页点 Python 条目右侧的国内直链(华为云 / npmmirror 独立安装包)重装即可; WebView2 与 VC++ 运行库提供的也是独立 exe 直链与 winget 命令,同样不经过商店。
  • 双击 bat 一闪而过? 在资源管理器地址栏输入 cmd 回车,把 bat 拖进去回车,看报错;或右键「用终端打开」。
  • 想用浏览器打开? pywebview 不可用时程序会自动改用浏览器;也可命令行 python app.py --browser。
  • 数据备份/迁移? 整个 data/ 文件夹即全部数据(文档备份+向量库+配置),拷走即可。

T术语表

RAG

Retrieval-Augmented Generation,先检索资料再让模型作答的技术范式。

Ingestion(文档摄入)

上传 → 解析 → 分块 → 向量化 → 入库的离线流程。

Chunk / Chunking(分块)

把文档切成可检索的小段;分块策略直接影响检索精度。

Embedding(嵌入)

把文本映射成向量。语义越近向量越近,是向量检索的基础。

向量库 / 稠密检索

存向量的仓库;按余弦相似度找"语义最近"的块。

BM25 / 稀疏检索

经典关键词打分算法;精确匹配术语与编号。

Hybrid Retrieval(混合检索)

稀疏 + 稠密同时召回再融合,兼顾精确与语义。

RRF

倒数排名融合: 1/(k+rank) 相加,融合两个排名榜单。

Rerank(重排)

用更强的模型对召回结果二次精排(进阶功能)。

Prompt(提示词)

发给模型的指令文本;RAG 的提示词内含"参考资料 + 引用规则"。

上下文窗口

模型一次能"看到"的 token 上限;分块 top_k 都会占用它。

幻觉 Hallucination

模型生成无依据内容;RAG + 引用机制是主要防线。
